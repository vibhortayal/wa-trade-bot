03 / PRIVACY BY DESIGN

Your server. Your schedule. Your keys.

Raw chat and WhatsApp identities are never published to the dashboard. The bot sends each message to the Gemini API you configure for extraction, then stores only structured, pseudonymized trade records for analysis.

  • Stable pseudonyms replace names and phone numbers
  • Secrets and the WhatsApp session stay on your own machine
  • Hourly pull-and-disconnect cycle instead of a permanent session
  • Open-source code makes every data boundary inspectable
04 / STACK

Boring tools, composed well.

01

whatsapp-web.js

Linked-device reader that connects, pulls messages since the last checkpoint, and disconnects. No permanent session, no spare phone.

02

Gemini API

Turns messy chat messages into structured trade records — symbol, action, instrument, strike, expiry, quoted context included.

03

TradingView

Daily market bars power the five-trading-day outcome scoring, round-trip detection, and target-hit checks.

04

Supabase

Postgres stores the pseudonymized trade records and sync metadata. The dashboard reads it live; row-level security keeps writes server-side.

05

Node.js + Python

Node drives the WhatsApp reader and setup UI; Python handles extraction, scoring, and the Supabase push. One shell script runs the whole cycle.

06

Vercel + Oracle Cloud

The dashboard is a dependency-free static site on Vercel; the pipeline runs on an Oracle Cloud Always Free VM — the whole thing costs nothing to operate.

05 / GET STARTED

From zero to live in an afternoon.

Gather the prerequisites, then hand the prompt below to your AI agent. Every step is verified against the actual installer and setup UI — no guesswork.

01

Oracle Cloud account

Always Free tier. One VM: Ubuntu 24.04, Ampere A1 shape (4 OCPUs / 24 GB RAM), public subnet with TCP ingress on port 3001. Free capacity comes and goes — retry provisioning if it fails.

02

WhatsApp on your phone

The bot pairs as a linked device with a one-time code. No spare SIM, no number changes.

03

Gemini API key

Free tier from Google AI Studio. Used only to turn chat messages into structured trade records.

04

Supabase project

Free tier. You need the project URL and the service_role key — writes stay on your VM while the dashboard reads with the anon key. The schema ships in the repo and inside the setup UI.

05

TradingView account

OPTIONAL  Only needed for the five-day outcome scoring. The pipeline runs fine without it.

The setup prompt

Set up Trade Flow end to end: https://github.com/vibhortayal/wa-trade-bot WHAT IT IS: an hourly pipeline on a VM. A WhatsApp linked-device reader pulls new messages from one trading group, Gemini extracts structured trade actions, TradingView market data scores each outcome over five trading days, and pseudonymized records land in Supabase for a static dashboard. PREREQUISITES — I have all of these ready: - Oracle Cloud Always Free account - Ubuntu 24.04 ARM VM (Ampere A1: 4 OCPUs / 24 GB RAM) with a public IP; subnet security list allows TCP ingress on port 3001 from 0.0.0.0/0 - My WhatsApp account on my phone (I can type in a pairing code) - Gemini API key (free tier) - Supabase project URL + service_role key - TradingView account (for outcome scoring) DO THIS IN ORDER. Verify each step before moving on. 1. DEPLOY THE CODE Copy the repo to the VM. The VM directory is NOT a git repo — always deploy with scp, never git pull there: scp -r . ubuntu@<VM-IP>:~/wa-trade-bot SSH in and install (Node 20, Python 3, Chromium, systemd units). It asks for a setup-UI admin password — have me choose one: ssh ubuntu@<VM-IP> bash ~/wa-trade-bot/deploy/install.sh 2. OPEN THE SETUP UI http://<VM-IP>:3001/setup.html — HTTP Basic Auth, any username + the admin password from step 1. (Plain HTTP: fine for setup over a trusted network; don't expose it more broadly than needed.) 3. LINK WHATSAPP In the UI, enter my phone number in international format (e.g. 15551234567) and get the pairing code — hand it to me immediately, codes expire. I type it into WhatsApp → Settings → Linked devices → "Link with phone number instead". Confirm the UI reports wa_paired: true before continuing. 4. SAVE THE KEYS In the UI, paste the Gemini API key, the Supabase URL, and the Supabase service_role key. Then run the SQL shown in the UI's schema box once in the Supabase SQL editor — it creates the wa_trades and wa_meta tables with anon read-only access. Leave GEMINI_MODEL unset; the default model is used. 5. SET THE GROUP Over SSH, set the trading group's name in ~/wa-trade-bot/.env: WA_GROUP_QUERY="your group name" (Substring match on the WhatsApp group name; the reader only touches group chats and stays within this one group.) 6. CONNECT TRADINGVIEW (outcome scoring) In the UI: start the TradingView auth, open the authorize URL, approve it, then paste the full callback URL (the one containing ?code=...) back into the UI. Tokens stay on the VM. Skip this if I don't need outcome scoring. 7. RUN THE FIRST CYCLE In the UI press "Run a cycle now" — or over SSH: MANUAL_RUN=1 bash ~/wa-trade-bot/run-cycle.sh It pulls recent messages, parses trades, scores outcomes, and pushes to Supabase. Verify the cycle exits 0 and new rows appear in the wa_trades table. 8. CONFIRM THE SCHEDULE sudo systemctl status wa-trade-bot-cycle.timer — the hourly pipeline runs 06:00–18:00 America/Los_Angeles only. Never schedule it overnight. 9. OPEN THE DASHBOARD http://<VM-IP>:3001/ — it reads live from Supabase. HARD RULES - Never print, log, or commit: .env contents, data/messages.jsonl (raw chat), data/pseudonyms.json, phone numbers, sender names, group IDs, API keys, the admin password, or pairing codes. They are gitignored — keep them that way. - No git pull on the VM. Ever. Deploy with scp. - PUPPETEER_EXECUTABLE_PATH must be /snap/chromium/current/usr/lib/chromium-browser/chrome (the real binary). /snap/bin/chromium does NOT work inside systemd services. - Keep whatsapp-web.js's default Chrome/101 user agent; newer user agents land on WhatsApp's unsupported-browser page. - If anything fails, show me the exact error plus the log tail (the UI "Logs" section, or logs/cycle.log on the VM) before retrying.
